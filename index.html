A workflow you can
actually follow.

Learn the spreadsheet method ↗
  1. 01

    Observe.

    Choose an authorized reference. Record repeatable behavior, sources and what you still don’t know.

  2. 02

    Model.

    Turn supported facts into stable IDs, fields and rules in your workbook. Keep hypotheses separate.

  3. 03

    Build.

    Validate the matrix. Make an original implementation that consumes your data, not scattered constants.

  4. 04

    Verify.

    Compare actual runtime behavior with your observations. Repeat, measure and document the gaps.

BEFORE YOU DIVE IN

Good questions.

Is RustPorts finished?

Not yet. The directory is live and the experimental Python workbook starter is runnable. The native Jcode integration is an unfinished development snapshot. We hope to complete the broader workflow soon, but there is no promised release date. See what is ready and what is next.

Do I need a server to list my project?

No. A public GitHub repository and project details are required. A direct server address is optional. If you offer one, you operate it yourself. Players follow your repository’s instructions and connect in the game’s own client.

What can I submit?

Rust game projects you have the right to share. Submit text details, a public GitHub URL and optionally your own server address. No game files are uploaded. Listings stay private until review, and edits return them to review. Read the submission terms.

Does rewriting something in Rust make it legally safe?

No. Rewriting, parody and self-hosting do not automatically grant rights or remove liability. Use original or properly licensed material, document permissions, and get qualified legal advice when needed. Report a rights concern.
